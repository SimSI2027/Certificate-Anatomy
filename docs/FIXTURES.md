# Fixtures

All fixtures are synthetic public artifacts generated by `npm run fixtures:generate` (`scripts/fixtures/generate.mjs`).

| File | Content |
| --- | --- |
| `fixtures/certificates/simsi2027-root-ca.cer` / `.pem` | Offline Root CA, self-signed, RSA 4096 |
| `fixtures/certificates/simsi2027-issuing-ca-01.cer` / `.pem` | Issuing CA, signed by the Root, pathLen 0 |
| `fixtures/certificates/app-simsi2027-test.cer` / `.pem` | Issued TLS server certificate |
| `fixtures/certificates/app-simsi2027-test-chain.pem` | Leaf, Issuing CA, Root, in that order |
| `fixtures/requests/app01-request.der` / `.csr` | The PKCS #10 request (DER and PEM) |
| `fixtures/requests/app01-request.inf` | Safe certreq-style request policy (no secrets) |
| `fixtures/crl/simsi2027-issuing-ca-01.crl` / `.crl.pem` | Issuing CA CRL 42, no revoked entries |
| `fixtures/crl/simsi2027-root-ca.crl` | Root CA CRL 3, no revoked entries |
| `fixtures/manifest.json` | Parsed metadata, thumbprints, SPKI hashes, file hashes, relationships |

## Private keys

Keys are generated with Node's `crypto.generateKeyPairSync`, held only in memory, used to sign, and discarded when the process exits. Nothing key-related is written to disk, so no temporary key directory exists.

## Reproducibility

Names, dates, serial numbers (derived from fixed labels), extensions, DER encoding rules and file layout are deterministic. Key material and therefore signatures change on each regeneration. A seeded key generator was rejected deliberately: committing a seed would be equivalent to committing the private keys. The committed files are the canonical set and are validated on every CI run.

## Validation

`npm run fixtures:validate` (also part of `npm test`) uses Node's own X.509 parser and crypto, plus OpenSSL when available, independently of the project's DER code. It checks 43 properties including: CSR self-signature, leaf signature by the Issuing CA and not by the Root, Issuing CA signature by the Root, Root self-signed, CSR public key equals leaf public key, SAN, EKU, Key Usage, Basic Constraints, AKI = Issuing CA SKI, AIA and CDP separate, validity nesting and the simulation clock (2 Nov 2026 09:45 UTC), chain order, CRL signatures and freshness, manifest hashes and thumbprints, and the request policy disclaimer.

## Regenerating

```bash
npm run fixtures:generate && npm run fixtures:validate && npm test
```

Serial numbers stay fixed. Keys, signatures, thumbprints and SPKI hashes change; the app reads all of them from the files at runtime.
